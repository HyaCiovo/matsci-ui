# <I18nText en="Building a Search UI" zh="搭建 Search UI" />

<I18nText
  en="Search UI is a composition pattern centered on `SearchUIContainer`. The container owns query state, request lifecycle, view switching, paging, and filter coordination."
  zh="Search UI 是一套以 `SearchUIContainer` 为中心的组合模式。容器负责查询状态、请求生命周期、视图切换、分页以及筛选器协同。"
/>

## <I18nText en="Core Building Blocks" zh="核心构建块" />

<I18nText
  en={
    <ul>
      <li>`SearchUIContainer`: top-level state, network, paging, sorting, and shared context</li>
      <li>`SearchUISearchBar`: free-form query entry with input-type detection</li>
      <li>`SearchUIFilters`: structured filters grouped into accordion-like sections</li>
      <li>`SearchUIDataHeader`: result summary, progress indicator, column controls, and view controls</li>
      <li>`SearchUIDataTable`, `SearchUIGrid`, `SearchUIDataView`: result rendering surfaces</li>
    </ul>
  }
  zh={
    <ul>
      <li>`SearchUIContainer`：顶层状态、网络请求、分页、排序与共享上下文</li>
      <li>`SearchUISearchBar`：带输入类型识别的自由检索入口</li>
      <li>`SearchUIFilters`：按分组组织的结构化筛选器面板</li>
      <li>`SearchUIDataHeader`：结果摘要、进度条、列控制和视图切换</li>
      <li>`SearchUIDataTable`、`SearchUIGrid`、`SearchUIDataView`：结果渲染层</li>
    </ul>
  }
/>

## <I18nText en="Typical Flow" zh="典型搭建流程" />

<I18nText
  en={
    <ol>
      <li>Define the `columns` that should be queried and rendered.</li>
      <li>Define `filterGroups` for structured query building.</li>
      <li>Pass `apiEndpoint`, `resultLabel`, and optional defaults into `SearchUIContainer`.</li>
      <li>Compose the child components that should consume the shared state.</li>
      <li>Use `searchOnMount={false}` when the target endpoint is expensive or requires user intent.</li>
    </ol>
  }
  zh={
    <ol>
      <li>先定义需要查询和渲染的 `columns`。</li>
      <li>再定义用于结构化筛选的 `filterGroups`。</li>
      <li>把 `apiEndpoint`、`resultLabel` 和默认参数传入 `SearchUIContainer`。</li>
      <li>组合需要消费共享状态的子组件。</li>
      <li>若目标接口昂贵或需要用户确认，优先设置 `searchOnMount={false}`。</li>
    </ol>
  }
/>

## <I18nText en="Minimal Example" zh="最小示例" />

```tsx
import {
  SearchUIContainer,
  SearchUISearchBar,
  SearchUIFilters,
  SearchUIDataHeader,
  SearchUIDataTable,
} from '@hyacinth/matsci-ui';

const columns = [
  { title: 'Material ID', selector: 'material_id' },
  { title: 'Formula', selector: 'formula_pretty', formatType: 'FORMULA' },
];

const filterGroups = [
  {
    name: 'Composition',
    filters: [
      {
        name: 'Formula',
        params: ['formula'],
        type: 'MATERIALS_INPUT',
        props: { type: 'formula' },
      },
    ],
  },
];

export function DemoSearchUI() {
  return (
    <SearchUIContainer
      apiEndpoint="/mp-api/materials/summary"
      columns={columns}
      filterGroups={filterGroups}
      resultLabel="material"
      searchOnMount={false}
    >
      <SearchUISearchBar
        allowedInputTypesMap={{
          formula: { field: 'formula' },
          elements: { field: 'elements' },
          mpid: { field: 'material_ids' },
        }}
      />
      <SearchUIFilters />
      <SearchUIDataHeader />
      <SearchUIDataTable />
    </SearchUIContainer>
  );
}
```

## <I18nText en="Accessibility" zh="无障碍" />

<I18nText
  en={
    <ul>
      <li>Filter groups expose `aria-expanded`, `aria-controls`, and `role="region"` for keyboard-friendly disclosure.</li>
      <li>Header controls and search affordances use explicit labels and stateful button semantics.</li>
      <li>When you add custom cell renderers, keep interactive targets keyboard reachable and label them explicitly.</li>
    </ul>
  }
  zh={
    <ul>
      <li>筛选分组使用 `aria-expanded`、`aria-controls` 和 `role="region"`，适合键盘用户操作。</li>
      <li>头部控件与搜索入口使用显式标签与按钮状态语义。</li>
      <li>如果你自定义单元格渲染器，请保证交互目标可键盘聚焦，并提供明确标签。</li>
    </ul>
  }
/>

## <I18nText en="Performance" zh="性能" />

<I18nText
  en={
    <ul>
      <li>Use `searchOnMount={false}` to prevent unnecessary initial requests.</li>
      <li>Prefer server-side pagination for large datasets.</li>
      <li>Keep `columns` and `filterGroups` stable with memoization in app code when the configuration is large.</li>
    </ul>
  }
  zh={
    <ul>
      <li>通过 `searchOnMount={false}` 避免初始无意义请求。</li>
      <li>面对大数据量时，优先使用服务端分页。</li>
      <li>当 `columns` 和 `filterGroups` 配置较大时，建议在业务代码里做 memo 化，保持引用稳定。</li>
    </ul>
  }
